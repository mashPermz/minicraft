# suggestion_box 運用ルール

開発の**運用改善**・**品質向上**・**楽しさの方向性のアイデア創出**のための目安箱。
人間(遊び手・オーナー)と Claude(開発担当)の双方が書き込み、次のバージョン開発の入力にする。

## ファイルの種類

| ファイル | 役割 | 書く人 |
| --- | --- | --- |
| `README.md` | この運用ルール | Claude(改訂はどちらでも) |
| `PRIORITIES.md` | 次バージョン候補の遊び手優先度(常に1枚を上書き更新) | 人間が優先度を記入、Claude が候補を補充 |
| `YYYY-MM-DD-<slug>.md` | 個別の提案・振り返り(1トピック1ファイル、または1セッション1ファイル) | どちらでも |

## 提案ファイルの形式

先頭に frontmatter を付ける。人間が書くときは **frontmatter なしの走り書きでよい**(次のセッションで Claude が整形する)。

```markdown
---
date: 2026-07-04
author: claude | human
category: ops | quality | fun   # 運用改善 / 品質向上 / 楽しさ
status: open | adopted | declined | done
---

本文(背景 → 提案 → 期待効果)。複数トピックはファイル内の見出しごとに
`[status: open]` を付けてもよい。
```

## ステータスのライフサイクル

- **open**: 未処理。次バージョンのスコープ検討時に必ず読まれる
- **adopted**: 次バージョンのスコープや運用に採用決定(どのバージョンかを本文に追記)
- **done**: 実施済み(コミット/PR番号を本文に追記)
- **declined**: 見送り(理由を1行残す。再提案は可)

ステータスの更新は「その提案に対して行動した人」が行う。

## ハーネス(いつ・誰が・何をするか)

1. **セッション開始時(Claude)**: `minicraft/CLAUDE.md` の指示により、開発セッションの冒頭で `status: open` の提案と `PRIORITIES.md` を読む。
2. **バージョンスコープ決定時(Claude)**: `PRIORITIES.md` の遊び手優先度 + open 提案からスコープ案を作り、独断で見送る場合も「見送りリスト」として本文か PR に明記する(会話内だけに残さない)。
3. **バージョン完了時(Claude)**: 開発フローの振り返りを1ファイル追加し、`PRIORITIES.md` の候補リストを更新する(実装済みを消し、新候補を足す)。
4. **随時(人間)**: プレイして感じたこと・アイデアを走り書きで投入する(形式自由。ファイル名も自由。次のセッションで Claude が整形・返信する)。
5. **返信の形式**: 提案への応答は同じファイルの末尾に `> [claude 2026-07-04] ...` / `> [human ...] ...` の引用形式で追記する(ファイルを分けない)。

## git 管理

suggestion_box はリポジトリにコミットする(開発ナレッジとして永続化)。
機微な内容やメモ書きを残したくない場合は、ファイル名を `_` 始まりにすると gitignore される。
